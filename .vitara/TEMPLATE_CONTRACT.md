# Template contract (v1): branding and languages

**Audience:** the template team, who build and migrate template repos.
**Platform side:** `ARCHITECTURE.md`. The reference implementation is
`backend/project_templates/template_manifest.py` (manifest rules) and `template_customize.py` (what the server writes).

A template that follows this contract gets the "Use template" pop-up: the user sets a brand (step 1) and chooses
languages (step 2). The server then edits fixed files before the first commit. No AI is involved, so every path and
format below is fixed. A template **without** `vitara.template.json` keeps working as before (no pop-up).

## 1. The manifest: `vitara.template.json` (repo root)

```json
{
  "version": 1,
  "branding": true,
  "locales": {
    "default": "en",
    "available": ["en", "fr", "de", "ar"]
  }
}
```

| Field | Rule |
|---|---|
| `version` | Always `1`. |
| `branding` | `true` when the template follows section 2. `false` or missing: no brand step. |
| `locales` | Optional. Missing: no language step. |
| `locales.default` | One of `available`. It is always kept, and it is the language the app opens in. |
| `locales.available` | 1 to 20 codes, no repeats, each from the list in section 4. Each must have a folder `src/locales/<code>/`. |

Unknown fields are refused, so typos are caught. After a change, an admin opens the template in the admin panel and
clicks **Sync from repo**. The server reads the manifest from the template's branch and stores it. Until then the old
manifest (or none) is used.

## 2. Branding

### 2.1 `src/config/brand.json`: the app reads its brand from here

```json
{
  "app_name": "Hospital Care",
  "tagline": "Care that comes to you",
  "primary_color": "#2563eb",
  "accent_color": "#f59e0b",
  "font": "Inter",
  "logo": "/brand/logo.png",
  "favicon": "/brand/favicon.png"
}
```

- The template ships this file with its own defaults, and its pictures in `public/brand/`.
- The app shows `app_name`, `tagline` and `logo` from this file. **Never hard-code them in components.**
- The server rewrites the file with 2-space JSON and a trailing newline. It keeps the template's value for every field
  the user left empty. `logo` and `favicon` are public paths, or `""` for none.
- The user's pictures are saved as `public/brand/logo.<png|jpg|webp>` and `public/brand/favicon.<png|jpg|webp>`.
  An old file with another extension is deleted.

### 2.2 `src/styles/brand.css`: generated, never edit it by hand

The app imports it once, before its own styles (for example `import "./styles/brand.css"` in `main.tsx`). The server
regenerates it from `brand.json`, so the template's own copy must be the generated output for its defaults.

```css
/* Generated by Vitara from src/config/brand.json. Do not edit: change brand.json instead. */
:root {
  --brand-primary: #2563eb;
  --brand-primary-rgb: 37 99 235;
  --brand-primary-foreground: #ffffff;
  --brand-primary-50: #f4f7fe;
  --brand-primary-50-rgb: 244 247 254;
  ... 100, 200, 300, 400, 500, 600, 700, 800, 900 ...
  --brand-accent: ...same set for the accent colour...
  --brand-font: "Inter", ui-sans-serif, system-ui, sans-serif;
}
```

Shades are mixed in sRGB and rounded to the nearest integer:

| Shade | 50 | 100 | 200 | 300 | 400 | 500 | 600 | 700 | 800 | 900 |
|---|---|---|---|---|---|---|---|---|---|---|
| Mixed with | white 95% | white 90% | white 75% | white 60% | white 30% | (base) | black 15% | black 30% | black 45% | black 60% |

`-foreground` is `#ffffff` or `#111827`, whichever has the higher WCAG contrast ratio with the base colour (a tie gives
white).

**Tailwind:** map the colours once in `tailwind.config`:

```js
primary: { DEFAULT: "rgb(var(--brand-primary-rgb) / <alpha-value>)", 50: "rgb(var(--brand-primary-50-rgb) / <alpha-value>)", /* ... */ },
fontFamily: { sans: ["var(--brand-font)"] },
```

### 2.3 `index.html`: the head block

`index.html` (project root) has this block in `<head>`, and **no other `<title>`, description meta or favicon link**:

```html
    <!-- vitara:brand:start -->
    <title>Hospital Care</title>
    <meta name="description" content="Care that comes to you" />
    <link rel="icon" href="/brand/favicon.png" />
    <link rel="preconnect" href="https://fonts.googleapis.com" />
    <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />
    <link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700&display=swap" />
    <!-- vitara:brand:end -->
```

The server replaces everything between the two markers. Text is HTML-escaped. The description and icon lines are left
out when empty. When the markers are missing, the block is added before `</head>` and any `<title>` is removed.

### 2.4 Fonts

Only these Google Fonts can be chosen (the list is in `template_customize.FONTS`):
Inter, Roboto, Open Sans, Lato, Montserrat, Poppins, Nunito, Raleway, Work Sans, DM Sans, Manrope,
Plus Jakarta Sans, Rubik, IBM Plex Sans, Noto Sans, Cairo (sans-serif); Playfair Display, Merriweather, Lora (serif).
For a template with Arabic, pick a font that covers it (Noto Sans, Cairo, IBM Plex Sans).

## 3. Languages

- Texts live in `src/locales/<code>/*.json`, one folder per language in `locales.available`. Every language has the
  same files and keys. The default language is complete.
- The app reads its list of languages from `src/config/locales.json` and never from a hard-coded list:

  ```json
  {
    "default": "en",
    "available": [
      {
        "code": "en",
        "name": "English",
        "dir": "ltr"
      }
    ]
  }
  ```

  2-space JSON, trailing newline, `name` is the native name, `dir` is `ltr` or `rtl`. The server rewrites it with only
  the languages the user kept, in manifest order. The template ships it with all its languages.
- The server deletes `src/locales/<code>/` for every manifest language the user did not choose. The code must not
  import a language folder directly: load it from the list (for example `import.meta.glob("../locales/*/*.json")`), so a
  deleted folder never breaks the build.
- A right-to-left language sets `dir="rtl"` on `<html>`; use logical CSS (`ms-`, `pe-`, `text-start`).
- With only one language left, the app hides its language switcher.

## 4. Language codes

`en`, `hi`, `es`, `pt-BR`, `fr`, `de`, `id`, `tr`, `ru`, `it`, `ar` (rtl), `pl`, `nl`, `ro`, `ar-MA` (rtl), `sr`, `sv`,
`el`, `da`, `fi`. The same as the Vitara app (`backend/localisation/languages.py`).

## 5. Removed when a project is created

`.vitara/`, `.github/workflows/vitara-template-check.yml` and `vitara.template.json`. Put template-only tooling
there. It never reaches the user's project.

## 6. `CLAUDE.md` section for the coding agent (add to the template's `CLAUDE.md`)

```md
## Brand and languages
- App name, tagline, logo, favicon, colours and font come from `src/config/brand.json`. Colours are CSS variables from
  `src/styles/brand.css` (generated, do not edit): use the Tailwind `primary` / `accent` colours, never a hex value.
- Every user-facing text is a translation key. When you add or change a text, update every folder in `src/locales/`.
  The languages are listed in `src/config/locales.json`.
```
